# Solver design

optimizam solves linear programs (LP) and mixed-integer linear programs
(MILP), in the style of [HiGHS](https://github.com/ERGO-Code/HiGHS);
constraint programming problems with a lazy clause generation engine, after
OR-Tools CP-SAT; and continuous nonlinear programs (NLP) with an interior
point method, after [IPOPT](https://github.com/coin-or/Ipopt). Problems
outside that scope are rejected with an error, as described below.

## Scope

A problem is linear when, after `sum`/`forall` are expanded and parameter
values are substituted, every constraint and the objective is an affine
function of the variables: a constant times each variable, plus a constant.
Linear problems may have integer variables and use every constraint kind.
In nonlinear problems (format 1.2), only `expr` constraints (without
`enforce_if`) and the objective may be nonlinear; they may have integer
variables (mixed-integer nonlinear programs) and the other constraint kinds
on affine terms.

- Allowed: `usage[r,p] * make[p]`, `x / 2`, `3 * (x + y)`, `cap * cap * x`,
  `exp(rate[i] * years) * x[i]`. Any expression of constants is fine,
  including functions and non-integer powers (format 1.2), evaluated when
  the model is built; a result that isn't a finite number, such as `ln(0)`,
  is an error.
- Nonlinear: `x * y`, `x ^ 2`, `1 / x`, `ln(x)`. This is decided on the
  expanded expression, not on the expression text, so `x*y - y*x` is
  linear.

### Errors

These are reported on stderr with exit code 1, and no result file is written
(see [cli.md](cli.md)). The message names the constraint instance, or the
objective, and the offending term, for example
`unsupported: nonlinear terms with integer or binary variables (mixed-integer
nonlinear programs): constraint link[3] is nonlinear and open is not
continuous`.

- A nonlinear term in a constraint kind other than `expr`, an `enforce_if`
  row, an index, or a condition.
- `"all"` with nonlinear terms.
- With `--engine=nlp` only: an integer variable in a nonlinear problem, or
  nonlinear functions that can't be evaluated at the starting point (such
  as `ln(x)` at the default start `x = 0`; the message asks for `start`
  values or bounds).
- `solve.solutions` is `"all"` and the problem has a `continuous` variable.

Integer variables without finite bounds are allowed with `"all"`. If such a
problem has infinitely many solutions, the run continues until the time
limit and reports `incomplete`. Without `--time`, it doesn't end.

## Nonlinear expressions

The model keeps nonlinear terms (format 1.2) instead of rejecting them:
each `expr` row without `enforce_if`, and the objective, is split into an
affine part (as for linear rows) plus at most one node of an expression graph
(`src/nlp/graph.rs`), in `LinearModel::nonlinear`. Rows without a nonlinear
part stay in `rows`. The other constraint kinds, `enforce_if` rows, indices,
and conditions must stay affine (or constant) and report an error otherwise.

The graph stores nodes in topological order and hash-conses them, so a
subexpression shared by several rows (`exp(-k * t)`, or `x[i]` itself) is one
node, evaluated once; `x * y` and `y * x` are the same node, and
`x*y - y*x` cancels to an affine row. Constant subexpressions are folded.
The ops are constants, variables, weighted sums, products, quotients,
integer powers, constant real powers, general powers `a^b`, and the eight
functions.

Derivatives are exact (automatic differentiation): a gradient by one reverse
pass over the nodes a root reaches, and the Hessian of a weighted sum of
roots (the Lagrangian) by forward-over-reverse: one reverse pass for the
adjoints, then per direction v a forward tangent pass and a reverse
second-order pass give H v. The Hessian's structural pattern comes from how
nodes combine their children (a product couples its children's variables, a
function couples its argument's with themselves), and directions are
compressed by greedy coloring of its columns (columns that share no row
share a direction, so a separable function needs one pass). Values outside a
function's domain come out NaN or infinite, for the caller to handle.

The derivatives are checked against central differences on random graphs,
and against SymPy (`tests/data/sympy_derivatives.json`, generated by
`tools/sympy_derivatives.py`) through the whole parse and model path.

## Nonlinear engine

`src/nlp/` solves continuous problems, nonlinear or not, with a primal-dual
interior point method after Wächter and Biegler, "On the implementation of
an interior-point filter line-search algorithm for large-scale nonlinear
programming" (Math. Programming 106, 2006), the algorithm of IPOPT. It finds
a local optimum: a point satisfying the KKT conditions. The linear algebra
is dense, for problems with up to a few hundred variables and constraints.

- Standard form (`nlp/mod.rs`): fixed columns become constants; each row
  becomes an equality `g(x) - b = 0`, or `g(x) - s = 0` with a slack `s`
  bounded by the row's bounds; a maximization is negated. Rows and the
  objective are scaled at the start so that no gradient entry exceeds 100.
  Rows without free variables are checked exactly (a violated one is
  `infeasible`).
- Start: each variable's `start` (default 0), clipped to its bounds and then
  pushed inside them (IPOPT's bound push, 1e-2 of the bound's magnitude);
  bound multipliers 1; equality multipliers by least squares.
- Each iteration factors the primal-dual KKT matrix of the barrier problem
  with a dense Bunch–Kaufman LDLᵀ (`nlp/ldl.rs`), which also gives its
  inertia. If the inertia isn't (n positive, m negative), it adds `dc` to
  the constraint block when the Jacobian looks rank-deficient (too few
  negative eigenvalues) and increases `dw` on the Hessian block otherwise,
  as in IPOPT. The Hessian is the exact Hessian of the Lagrangian from the
  expression graph.
- Steps keep a fraction `max(0.99, 1 - mu)` of the distance to the bounds.
  A backtracking filter line search (infeasibility vs. barrier objective,
  with an Armijo condition when the step is dominated by optimality and a
  rounding allowance of 10 eps in the comparisons) accepts them, with up
  to four second-order corrections against the Maratos effect. A trial point
  outside a function's domain (NaN or infinite values) cuts the step back.
- The barrier parameter starts at 0.1 and decreases monotonically
  (`mu <- max(tol/10, min(0.2 mu, mu^1.5))`) when the barrier problem's
  optimality error is below `10 mu`.
- When no step is acceptable, the restoration phase minimizes
  `1000 * sum(p + n) + sqrt(mu)/2 ||D (x - x_r)||^2` subject to
  `c(x) - p + n = 0` with the same algorithm, until the original filter
  accepts a point with 10% less infeasibility. If it converges without
  that, the problem is locally infeasible. From a point that already meets
  the acceptable tolerance, the method stops instead.
- All bounds are relaxed by 1e-8 of their magnitude (IPOPT's
  `bound_relax_factor`), so feasible sets without an interior still have
  one. A reported point is moved back onto the bounds unless that breaks a
  row.
- Convergence: the scaled optimality error (dual infeasibility, constraint
  violation, complementarity, as in IPOPT) at most 1e-8, or at most 1e-6
  for 15 iterations in a row; and in the problem's own units, every row
  within 1e-6 of its bounds (relative to `1 + |bound|`). At most 3000
  iterations.

Before the local solve, the engine bounds the problem over its box
(`nlp/interval.rs`, `nlp/fbbt.rs`, `nlp/relax.rs`):

- Bound propagation (FBBT): node ranges by interval arithmetic, rounded
  outward, forward from the variables' bounds; then backward from each
  row's bounds (loosened by the feasibility tolerance) through each op's
  inverse (a sum's other terms, a product's other factor when it excludes 0,
  roots of powers, `ln` for `exp` and `exp` for `ln`, and so on), repeated
  to a fixed point. Functions are restricted to their domains, so `ln(x)`
  implies `x >= 0`.
- A linear relaxation over the propagated box: a column per node, with
  McCormick envelopes for products (and quotients as products), tangents
  and secants for powers and functions on intervals where their curvature
  has one sign, and the nodes' ranges as bounds; rows from extreme bounds
  (coefficients above 1e8 or spread over more than 1e9) are left out. The
  simplex method minimizes the objective over it, for a lower bound.
- An empty range or an infeasible relaxation proves that no point satisfies
  the rows: `infeasible`, unless the local solve finds a feasible point
  anyway (then the proof was a numerical failure and is ignored, as is a
  bound above a feasible point's objective). A start outside the implied
  bounds (`x = 0` under `ln(x)`) moves inside them. A local optimum within
  1e-6 (relative to `1 + |f|`) of the relaxation's bound is proven global:
  `complete`. That happens for convex problems whose nonlinear terms the
  relaxation captures exactly enough (sums of convex univariate terms, sums
  of squares at 0); branching on the box (spatial branch and bound) is what
  closes the rest.

The sampling tests check every piece against the true values: enclosures
contain the ops' values, propagation never removes a sampled feasible
point, every relaxation row holds at the nodes' true values, and the
bounds are at most every sampled feasible objective.

`--engine=nlp` runs this local engine alone (on continuous problems, linear
or not). IPOPT (through CasADi, `tools/ipopt.sh`) is its development
reference, and `tools/nlp_benchmark.py` runs it on the Hock–Schittkowski
test problems.

## Global search (spatial branch and bound)

`--engine=auto` solves every problem with nonlinear terms globally
(`src/nlp/global.rs`), with continuous and integer variables:

- At the root, the variables of nonlinear terms are also tightened by
  optimization-based bound tightening: each is minimized and maximized
  over the relaxation (two rounds), which bounds variables that only
  several linear rows together bound; the LP's values are loosened by 1e-6
  relative, and only well-scaled relaxations are used.
- A node is a box of variable bounds. Bound propagation tightens it, with
  the objective required to beat the incumbent (an empty box is pruned);
  integer bounds are rounded inward. The linear relaxation over it gives
  the node's lower bound, with tangents at the incumbent and up to three
  cutting-plane rounds (tangents at the last relaxation's solution, while
  the bound improves). Sums that are convex (or concave) quadratic
  functions of affine terms, checked by the inertia of their constant
  Hessian, get tangent planes of the whole function, which captures convex
  quadratic programs that the products' McCormick envelopes alone can't.
  The cutoff isn't a row of the relaxation: its bound is compared with the
  incumbent instead (near the optimum, the cutoff makes the LP infeasible by
  margins too thin to confirm); a box whose relaxation has no bound under
  the cutoff is bounded again without it. The objective's range from
  propagation is a bound as well, independent of the LP. An infeasible
  relaxation prunes a box only if the elastic LP confirms it and the
  relaxation's coefficients span at most 1e10: the simplex method's
  verdicts on worse-scaled LPs (as in MINLPLib's ex14_1_9, with
  coefficients from 1e-3 to 2e9) aren't reliable, so those boxes are
  branched on instead.
- Pruning: a node whose bound is within the gap of the incumbent, with the
  gap `max(1e-4 |f|, 1e-5)` (relative 1e-4, the usual default of global
  solvers). So `complete` means proven optimal within that gap.
- A box that can't be split any more (all its variables narrower than
  1e-9) offers its points at the feasibility tolerance before it is
  dropped, so a feasible box is never lost.
- Reduced-cost bound tightening: with the relaxation's optimum z and
  reduced costs d (the simplex method returns them), a column at its lower
  bound l with d > 0 can only rise to l + (cutoff - z) / d before the
  relaxation's objective passes the cutoff (the incumbent minus the gap),
  and likewise at its upper bound; the box's children start from the
  tightened bounds (loosened by 1e-7 relative).
- A point is feasible only if its rows are verifiable: the rounding in
  evaluating a row (16 eps times its terms) must be within the row's
  tolerance. Branching on unbounded variables can reach points like 1e25,
  where `4x - 3y` evaluates to 0 though it is 6e9.
- Branching: on the most fractional integer variable; else on a variable of
  the nonlinear term that the relaxation's solution violates most (the
  widest of its variables), at that variable's value in the solution, kept
  10% of the width away from the box's ends.
- Incumbents: from the relaxation's solution if it satisfies the rows to
  1e-9 (much tighter than the feasibility tolerance, so that the search
  doesn't chase objective gains that exist only within it), and from local
  solves (the interior point method, inside the node's box, from the
  relaxation's solution, with integer variables rounded and fixed) at the
  root (also from the problem's start, and from other starts if that finds
  nothing), at depth 3 or less, and every 25 nodes. The final optimum is
  polished by a local solve.
- Nodes are taken best bound first, so the smallest open bound is a valid
  bound on the optimum. The search stops at the time limit; without one,
  after 2000 nodes; and when stalled: over the last 2000 nodes, the gap
  between the incumbent and the global bound shrank by less than 5% (or,
  with an incumbent, the bound stayed infinite for 6000 nodes). Stopped early, the
  answer is `locally_optimal` (the incumbent is a local optimum of a
  continuous problem, polished if needed) or `not_proven_optimal`, with the
  open nodes' bound as `objective_bound`.
- A nonlinear term of a variable without finite (implied) bounds may never
  be closed by splitting boxes, though propagation and the incumbent's
  cutoff often bound the pieces: the search branches anyway, with a budget
  of 500 nodes instead of 2000 when there is no time limit. After the
  root's local solve, propagation with the incumbent's cutoff bounds the
  root box, which bounds variables that only the objective bounds. Without
  any feasible point, a search whose root local solve converged to a local
  minimizer of the infeasibility reports `locally_infeasible`.
- The graph keeps scale factors out of products, quotients, and powers
  ((c u) v is c (u v)) and flattens sums of sums, so that `u v` is one node
  (one McCormick envelope, one relaxation column) for every row that uses
  it, whatever its coefficient there, and a sum built term by term is one
  node rather than a chain of partial sums.
- Convexity (`src/nlp/convexity.rs`): each node's curvature over the box,
  by the composition rules of convex analysis with the signs of f' and f''
  from interval arithmetic, plus products of powers (weighted geometric
  means are concave, negative powers convex), exponentials `c^g`, and
  entropy terms `u (c + ln u)` and `u (c + ln(u / v))`. Each composite node
  that is convex (concave) on the box gets outer-approximation cuts: its
  tangent plane in the variables, at the box's center and at each hint
  point.
- Convex problems with integers (`src/nlp/ecp.rs`): when every nonlinear
  row is convex in its bounded direction and the objective is convex on
  the root box, outer approximation on the MILP engine runs before
  branching: cuts at the continuous relaxation's solutions (LP solves)
  until its bound stalls, keeping the tight ones; then MILP rounds, with
  cuts at the MILP's solution where violated and at the local solution
  with the integers fixed (Duran–Grossmann), until the MILP bound meets the
  incumbent (proven), the MILP is infeasible (so is the problem), or the
  bound stalls for 5 rounds (branching takes over). An equality row that
  defines a variable only the objective uses (`f(x) - objvar = 0` with
  `min objvar`) relaxes to its convex side.
- Relaxation LPs are scaled (geometric-mean equilibration by powers of 2)
  and have a fixed shape: the same rows for every box, free where an
  estimator doesn't apply, then one block per hint point. A box hands its
  hint points and final basis to its children, which start from it;
  cutting-plane rounds append blocks and extend the basis.
- Scheduling constraints are encoded as linear rows first, as for MILP.

The global search is checked against brute force (random nonconvex
problems in two variables, some with an integer variable, against a fine
grid; a mixed-integer problem against enumeration), against SCIP
(`tools/compare_global.py`: random problems, feasible and infeasible), and
against published proven optima (the Hock–Schittkowski problems, and
MINLPLib through `tools/minlp_benchmark.py`, which flags any proof that
contradicts the known optimum).

## Numerics

The solver uses `f64` with tolerances, like HiGHS:

- Primal and dual feasibility tolerance: about 1e-7.
- Integrality tolerance: about 1e-6.
- When collecting all optimal solutions, a solution ties the optimum if its
  objective value is within the optimality tolerance of it.

In result files, integer and binary values are rounded to exact integers.

## Algorithms

1. **LP: bounded dual simplex.** It handles variable bounds directly, and it
   can quickly re-solve after bound changes, which branch and bound relies on.
   The first version uses dense matrices. Later it moves to a sparse LU
   factorization of the basis, refactored from scratch periodically, with our
   own update when a column is replaced (as HiGHS's `HFactor` does).
2. **MILP: branch and bound** on the LP solver. Each child node starts from its
   parent's final basis. The time limit is checked between nodes. Nodes are
   explored depth-first until the first integer solution, then best-bound.
   The branching variable is chosen by reliability branching: pseudocosts
   (average objective gain per unit bound change), with strong branching for
   variables that have too few observations. Before the search, each row
   whose variables are all integer, with integer coefficients, has its bounds
   rounded inward to multiples of the coefficients' gcd. An empty range proves
   infeasibility, which branch and bound alone may never show when the
   variables are unbounded (for example `2x - 4y = 7`).
3. **All optimal / all feasible solutions:** don't prune a node whose bound
   ties the best solution found, and collect every integer solution that
   reaches the optimum. A `satisfy` problem is solved with a zero objective.
4. **Cutting planes at the root,** in rounds until the bound stalls (`src/cuts/`):
   complemented MIR (c-MIR) cuts on aggregated rows, after Marchand and
   Wolsey and HiGHS's path separator, and Gomory mixed-integer cuts from the
   optimal tableau. Aggregation follows short paths through continuous
   variables, and for a few rows also projects all continuous variables out,
   which finds global counting cuts such as "total capacity covers total
   demand". Variable upper bounds such as `serve <= demand * open` are
   substituted into the MIR. Cuts no longer binding are removed between
   rounds, and the rest stay as rows for the whole search. Cuts are skipped
   with `"all"`, where a numerically unsafe cut could drop a tied optimum,
   and with a zero objective.
5. **Presolve** (`src/presolve.rs`), before branch and bound, in passes until
   nothing changes: fixed columns substituted out; empty, singleton,
   redundant, and forcing rows removed; implied bounds from row activities
   (integer bounds rounded and snapped to the domain); congruences on
   equality rows over integer columns (decimal coefficients scaled to
   integers; a small-range column keeps only values that satisfy the row
   modulo the gcd of the other coefficients); and coefficient
   tightening of binary columns in one-sided rows, which turns a loose big-M
   such as `make <= M * on` into `make <= U * on`. With `"one"`, dual
   reductions also fix a column at a finite bound when its cost doesn't
   favor leaving it and no row restricts it there. Only reductions with a
   trivial postsolve are used: a removed column has a fixed value, and a
   removed row is implied by what remains. Without dual reductions, presolve
   keeps every integer-feasible point, so it is safe with `"all"`.
6. **Primal heuristics** (`src/heuristics.rs`), to find good solutions early:
   simple rounding in lock-free directions; diving (fractional, coefficient,
   and guided toward the incumbent) with one backtrack; RENS at the root and
   RINS during the search, as sub-MIPs with a node limit solved by presolve
   and branch and bound themselves. They run at the root, then periodically,
   using at most about a fifth of the search time. Every solution they find
   is checked against the original rows.
7. **Bound propagation** (`src/propagation.rs`) at every node and in
   strong-branching probes, before the LP: implied bounds from row
   activities, with a trail of bound changes and their reasons. Conflict
   analysis by dual proofs was tried (branch `conflict-dual-proofs`) and not
   merged: correct, but no faster on our benchmarks.
8. **Deferred:** presolve reductions that need a real postsolve (doubleton
   equations, free column singletons, dominated columns, parallel rows),
   probing, and cuts below the root.

## CP engine

For problems whose variables are all integer with finite bounds, a second
engine (`src/cp/`) uses lazy clause generation, as OR-Tools CP-SAT does:

- Literals are integer bounds, `[x >= v]` and `[x <= v]`; the integer trail
  records each bound change with its reason and decision level, and can read
  back a bound as of any earlier trail position.
- Rows are scaled to integer coefficients and propagated on bounds in exact
  arithmetic (`i128` activities). Explanations are lazy: a bound implied at
  trail position p is explained by the other terms' bounds as of p. Rows of
  binaries such as `sum <= 1` need no special propagator: the explanation of
  each fixing is the single literal of the variable set to 1.
- CDCL search: 1-UIP conflict analysis with backjumping, VSIDS branching with
  phase saving (smallest value first), Luby restarts, and deletion of learned
  clauses by LBD.
- `"all"`: each solution is forbidden by a clause negating its decisions
  (propagation from them fixed every variable, so it is the only solution
  they allow), resolved as a conflict.
- Optimization: after each solution, the objective row is tightened to
  `<= value - 1`, and the search continues with its learned clauses.
  Optimization with `"all"` then enumerates every solution with objective
  `<=` the optimum in a fresh search, since the first search's learned
  clauses assumed a strictly better objective.

The format 1.1 constraint kinds are encoded in the front end
(`src/encode.rs`) as linear rows on extra columns, so both engines can solve
them. The common tool is a column's value encoding: a binary `[x = v]` per
value, with `sum_v [x = v] = 1` and `sum_v v [x = v] = x`, built once per
column and shared. It lets the CP engine remove values from inside a domain,
which bound literals alone can't express.

- `all_different`: for each value, at most one item takes it (an item over
  several columns first gets a column equal to it).
- `table`: a binary per distinct allowed tuple, exactly one chosen, and each
  variable equal to the chosen tuple's entry. Forbidden: for each tuple, the
  sum of its value binaries is at most n - 1.
- `element`: a selector binary per index combination of the array's
  comprehension (after its condition), exactly one chosen; each index equals
  the chosen combination's element, and the value equals the chosen item:
  exactly for constant items, by big-M pairs when items contain variables.
- `enforce_if`: with L the number of false literals (a binary, its negation,
  or a value binary `[x = v]`), the row is relaxed by M L on each side, M from
  the row's activity bounds.
- `max` (`min` mirrored): value >= every item, and a selector for the item
  that attains the maximum, with value <= that item (big-M otherwise).
- `abs`: value >= of and >= -of, and a sign binary choosing which bound is
  tight (big-M).
- Ties would leave selectors free and make `"all"` report a solution more
  than once, so for integer-valued items tie-breaking rows make them unique:
  `max`/`min` select the first extreme item, and `abs` has its sign binary 1
  exactly when of >= 0. `"all"` with items that aren't integer-valued is an
  error.
- Intervals: an interval's duration is at least 0 when it is present.
  `no_overlap`: for each pair, an order binary o, with o = 1 meaning the
  first ends by the time the second starts, and o = 0 meaning the second
  ends by the time the first starts and the first ends after the second
  starts; each applies only when both are present, and o is 0 otherwise. So
  o is unique, and the zero-length cases match CP-SAT. `cumulative`:
  time-indexed, with a binary per interval and time for "present, started,
  not ended", linearized exactly from the value binaries of the start (and
  end), and the demands at each time at most the capacity; a horizon of at
  most 10,000 time steps. These two are encoded only for the MILP engine;
  the CP engine propagates them natively (below).
- Symbolic values are their 1-based positions in their set; an element
  outside the set makes a tuple never match and a literal constant.

Columns may have at most 10,000 values each, and bounds must be finite where
a value encoding or a big-M needs them. Every added column is determined by
the original ones, so `"all"` enumerates each solution once, and they don't
appear in results. (The MILP engine's enumeration for `"all"` fixes one
column at a time, so it is slow on these encodings; auto picks CP for them.)

The CP engine propagates `no_overlap` and `cumulative` natively
(`src/cp/scheduling.rs`) instead of solving their encodings, so the model
keeps them aside (`LinearModel::scheduling`) and encodes them only when the
MILP engine is chosen. Presolve sees only the rows, so the columns they use
are frozen against dual fixing, and their instances are mapped through
presolve's column removal (fixed columns become constants, tasks fixed absent
are dropped). Each task is [start, end) with end = start + duration (an extra
variable when both vary); bounds pushed by these propagators are stored with
their explanations, which conflict analysis reads like any other reason.
Every rule also runs with time mirrored, to pull ends down.

- `cumulative`: timetabling over the compulsory parts [latest start,
  earliest end) of present tasks. A profile above the capacity is a
  conflict; otherwise it bounds a variable capacity from below. A task that
  would overload a time it covers at its earliest start must start after
  that time, explained by the tasks covering it, the capacity's bound, and
  the task's own bounds; an optional task that fits nowhere is absent.
- `no_overlap`: pairwise precedences (if a can't end by the time b starts,
  b ends by the time a starts; an optional task that fits neither way is
  absent), which are exact once tasks are fixed, zero-length ones included;
  and edge finding (for tasks within [a, b] with total duration P, another
  task that can't fit with them before b starts at a + P or later; a + P > b
  is a conflict). Edge finding is cubic in the number of tasks, so it is
  skipped above 200.

With scheduling constraints, branching until the first solution is
scheduling-aware: among the present tasks whose start isn't fixed, the one
that can start earliest (ties: end earliest) starts as early as it can.
That builds schedules left to right, which finds good first solutions
quickly. After the first solution the search uses VSIDS, whose phase saving
then starts from the solution; the fixed order is poor at proving optimality.

Optimization alternates, once there is a solution, between the main search
and large neighborhood search (`src/cp/lns.rs`, as in CP-SAT). The main
search runs until 1000 conflicts pass without a solution; then LNS rounds
spend up to as many conflicts again (halving after a phase without an
improvement, down to an eighth, and doubling after one with an improvement).
A round builds a fresh solver with `objective <= best - 1` and restrictions
that the incumbent satisfies, starts it from the incumbent's values, and
searches with a conflict limit (each round counts for at least a few
conflicts, so the phases end when every sub-problem fails at the root, as at a
proven optimum). An improvement tightens the main search's objective row and
resets its phases to the new solution. Only the main search proves
optimality. Neighborhoods, by start variable with scheduling constraints:
some tasks are relaxed (at random, a run in incumbent start order, or all
tasks of random resources), and the others keep their incumbent order but
not their times. On a `no_overlap` that means a chain `end <= start` through
them. On a `cumulative`, they are split into unit-capacity lanes (greedy
interval partitioning, a task of demand d on d lanes) with a chain per lane.
Without scheduling constraints, a random subset of columns is fixed. Each
neighborhood kind's relaxed fraction grows when its rounds finish within the
limit and shrinks when they don't. The random choices use a fixed seed, so
the search stays deterministic. `OPTIMIZAM_NO_LNS=1` turns LNS off.

`--engine=auto` (the default) uses the CP engine for problems it can take
that are `satisfy`, `"all"`, or use a format 1.1 constraint kind, after
presolve, and the MILP engine otherwise;
`--engine=mip|cp` overrides (see [cli.md](cli.md)). CP has no LP bound, so a
time-limited optimization reports no `objective_bound`. OR-Tools CP-SAT is
its development reference.

## Mapping to result statuses

| Situation | `status` |
|-----------|----------|
| LP solved to optimality / B&B tree exhausted | `complete` |
| LP proven infeasible / B&B tree exhausted with no integer solution | `infeasible` |
| LP proven unbounded | `unbounded` |
| Time limit, MILP, incumbent found, gap not closed | `not_proven_optimal` (with `objective_bound`) |
| Time limit, `"all"` requested, some valid solutions found | `incomplete` |
| Time limit, no feasible solution found | `timeout` |
| Nonlinear, global search: no open node left, with an incumbent | `complete` |
| Nonlinear, global search: no open node left, without one | `infeasible` |
| Nonlinear, global search: stopped (time, node limit, stall) with a local optimum of a continuous problem | `locally_optimal` (with `objective_bound`) |
| Nonlinear, global search: stopped with another feasible point (integers) | `not_proven_optimal` (with `objective_bound`) |
| Nonlinear, global search: stopped without a feasible point | `timeout` (or `locally_infeasible`, see above) |
| `--engine=nlp`: a local optimum (KKT point) | `locally_optimal` |
| `--engine=nlp` on a linear problem, `satisfy` with a feasible point, or a local optimum that the root relaxation's bound proves global | `complete` |
| `--engine=nlp`: bound propagation or the relaxation proves no feasible point exists (and the local solve found none) | `infeasible` |
| `--engine=nlp`: the restoration phase converged without a feasible point | `locally_infeasible` |
| `--engine=nlp`: time or iteration limit, or numerical failure, with a feasible point | `not_proven_optimal` (no `objective_bound`) |
| `--engine=nlp`: the same without a feasible point | `timeout` |

### MILP with an unbounded LP relaxation

When the LP relaxation is unbounded, the MILP is either unbounded or
infeasible. HiGHS can report this as "unbounded or infeasible". We always
decide which:

1. Run branch and bound with a zero objective to look for any
   integer-feasible point.
2. If one is found, report `unbounded`. With rational data, a feasible MILP
   whose relaxation is unbounded is itself unbounded (Meyer's theorem), and
   values parsed from JSON are rationals.
3. If the search proves that no such point exists, report `infeasible`.
4. If time runs out first, report `timeout`.

## Dependencies

- Runtime: `serde` (with `derive`), `serde_json`, and `clap` (with `derive`).
  Add no others without asking. All of the math is our own code.
- Possible later addition: `faer`, used only to refactor the basis
  periodically. It has no update for a replaced column, so we would write that.
- Development only: HiGHS (`highspy`) and OR-Tools (`ortools`, for CP-SAT) in
  `.venv` as references for comparing objective values and statuses. They are
  not dependencies of optimizam.
